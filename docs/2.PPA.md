# 📘 PROGRAMMATŪRAS PROJEKTĒJUMA APRAKSTS
**Projekts:** Tournament Bracket Web Aplikācija  
**Izstrādes valoda:** Python  
**Front-end:** HTML + CSS + Bootstrap (vai ekvivalents)  
**Datu saglabāšana:** JSON  
**Lietotāju autentifikācija:** config file (plain-text paroles)  
**Lomas:** Skatītājs (publisks), Pārvaldnieks (ar login)  
**Turnīra tips:** Single Elimination ar spēli par 3. vietu

---

# 1. Ievads

## 1.1. Dokumenta mērķis
Šis Programmatūras projektējuma apraksts (PPA) definē turnīra pārvaldības tīmekļa sistēmas arhitektūru, komponentes, datu struktūras un galvenās loģiskās plūsmas. Dokuments balstīts uz apstiprināto Programmatūras prasību specifikāciju (PPS.md) un kalpo kā tehniskais pamats sistēmas realizācijai.

## 1.2. Sistēmas konteksts
Izstrādājamā sistēma ir tīmekļa aplikācija turnīru organizēšanai pēc single elimination principa ar spēli par 3. vietu. Sistēma paredzēta nelieliem un vidēja apjoma turnīriem, izmantojot vienkāršu, uzturamu arhitektūru bez datubāzes servera.

---

# 2. Sistēmas pārskats
Turnīra pārvaldības sistēma ir vienkārša Flask aplikācija, kas nodrošina:

* skatītājiem → bracket skatu, turnīra tabulu, sākumlapu

* administratoriem → spēlētāju pārvaldību, raundu ģenerēšanu, rezultātu ievadi, atiestatīšanu

Sistēmas lietotāji:  
* **admin** (ar pieslēgšanos)  
* **viewer** (anonīms)  

Struktūra ir pilnībā balstīta uz HTML šabloniem + Flask backend.

## 2.1. Lietotāju lomas

- **Skatītājs (viewer)**
  Anonīms lietotājs, kurš var apskatīt turnīra bracketus un rezultātu tabulu.
- **Pārvaldnieks (admin)**
  Autentificēts lietotājs, kurš pārvalda turnīru, spēlētājus un rezultātus.

## 2.2. Funkcionālais sadalījums

- Publiskā sadaļa (viewer)
- Administratīvā sadaļa (admin)
- Biznesa loģikas servisi
- Datu persistences slānis (JSON faili)

Failu nozīme:

**app.py** – galvenais Flask entry-point:
* inicializē Flask aplikāciju;
* ielādē konfigurāciju (config.json);
* reģistrē maršrutus (public / admin);
* konfigurē sesijas (secret key).

**config.json** – konfigurācijas fails:
* turnīra nosaukums;
* admin lietotājvārdi + paroļu hash;
* citi globāli parametri (piem., datu faila ceļš).

**services/** – biznesa loģika un datu apstrāde:
* `auth_service.py` – autentifikācija un autorizācija;
* `tournament_service.py` – turnīra datu ielāde/ saglabāšana, reset funkcijas;
* `bracket_service.py` – bracket ģenerēšana, BYE loģika, 3. vietas spēle, uzvaru aprēķins.

**models/** – datu struktūras:
* `entities.py` – (pēc vajadzības) Player, Match, Round datu klases/struktūras loģiskākai apstrādei.

**data/**:
* `tournament.json` – reālais turnīra stāvoklis (spēlētāji, raundi, mači, rezultāti).

**templates/**:
* `base.html` – galvenais Bootstrap layout (header, navbar, base CSS/JS).
* `viewer_*` – publiskās (skatītāja) lapas.
* `admin_*` – admina lapas ar atsevišķu layout (admin_layout.html) un saturu.

**static/**:
* `styles.css` – nelieli dizaina pielāgojumi virs Bootstrap;
* `bracket.js` – ja vajadzēs nelielu JS, lai dinamiskāk zīmētu/formatētu bracketu (kaut gan var iztikt tikai ar HTML+CSS).

## 6.2. Datu klases

```

```

**Match**

# 7. Servisu slāņa apraksts

## 7.1. auth_service

Atbild par:
   * admin lietotāju ielādi no `config.json`;
   * paroļu hashu pārbaudi:
     * `verify_credentials(username, password)` → True/False (+ user info);
   * dekoratoru `login_required(view_func)` implementāciju:
     * pārbauda Flask session vai lietotājs ir ielogojies;
     * ja nav – redirect uz `/admin/login`.

Sesijā var glabāt, piemēram, `session["admin_username"]`.

## 7.2. tournament_service

Atbild par:
* turnīra datu ielādi un saglabāšanu:
  * `load_tournament()` – nolasa tournament.json
  * `save_tournament(data)` – ieraksta atpakaļ failā
* helper funkcijas (spēlētāju pievienošana, labošana un dzēšana; turnīra reset):
  * `reset_progress()` – notīra rezultātus (`winner_id = null`, `status = not_started`, bet atstāj spēlētājus)
  * `reset_all()` – iztīra spēlētāju sarakstu, roundus, statusu
  * `add_player(name)`
  * `remove_player(player_id)`
  * `update_player(player_id, new_name)`

Var saturēt arī funkciju `get_standings()` (bet to var likt `bracket_service.py`, jo tas izmanto maču rezultātus).

## 7.3. bracket_service

Atbild par turnīra loģiku:

1. Bracket ģenerēšana ar BYE:
   * `generate_bracket(players)`:
     * aprēķina tuvāko `2^k ≥ n`;
     * nosaka, cik BYE nepieciešami;
     * randomizē spēlētāju sarakstu;
     * izveido pirmā raunda mačus:
       * BYE mačiem automātiski iestata uzvarētāju (`winner_id = player_id`, `is_bye = true`);
     * izveido tukšos nākamos raundus (bez spēlētāju ID, līdz būs zināmi uzvarētāji).
2. 3.vietas spēles izveide:
   * pēc pusfinālu pabeigšanas:
     * identificē abu pusfinālu zaudētājus;
     * izveido/atjauno 3.vietas maču ar šiem spēlētājiem.
3. Rezultātu reģistrācija:
   * `set_match_winner(tournament, round_id, match_id, winner_player_id)`:
     * uzstāda `winner_id`;
     * ja raunda visi mači pabeigti:
       * uzģenerē nākamā raunda dalībniekus;
       * ja tas bija pusfināls – uzstāda final/third place dalībniekus.
4. Rezultātu tabulas aprēķins:
   * `calculate_standings(tournament)`:
     * iet cauri visiem mačiem;
     * krāj wins, losses, games katram spēlētājam;
     * atgriež sarakstu:
       * `[{player_id, name, wins, losses, games}, ...]`
     * sakārtots pēc wins desc, losses asc, name.

# 8. Flask maršruti (app.py)
## 8.1. Publiskie maršruti (skatītājs)
* `GET /` → redirect uz `/viewer`
* `GET /viewer`:
  * var noklusēti rādīt bracketu vai aggregatoru (tabs).
* `GET /viewer/bracket`:
  * nolasa turnīru;
  * padod uz `viewer_bracket.html`:
    * turnīra nosaukumu;
    * raundu/match struktūru.
* `GET /viewer/standings`:
  * nolasa turnīru;
  * izsauc `calculate_standings`;
  * padod tabulu uz `viewer_standings.html`.

## 8.2. Admin maršruti
* GET /admin/login – login forma.
* POST /admin/login – apstrādā login:
  * izmanto auth_service.verify_credentials.
* GET /admin/logout – iztīra sesiju, redirect uz /.

Visi zemāk minētie maršruti aizsargāti ar login_required:

* GET /admin vai /admin/dashboard:
  * īss pārskats: cik spēlētāju, statuss, pogas uz sadaļām.
* GET /admin/players:
  * rādīt sarakstu;
  * forma jauna spēlētāja pievienošanai.
* POST /admin/players/add
* POST /admin/players/delete/<player_id>
* POST /admin/players/update/<player_id>
* GET /admin/bracket:
  * ja bracket nav izveidots:
    * poga “Ģenerēt bracketu”.
  * ja bracket ir izveidots:
    * rāda pārus;
    * ļauj rediģēt (pirms pirmā raunda starta).
* POST /admin/bracket/generate
* POST /admin/bracket/update:
  * manuāla spēlētāju pāru korekcija (piem., nosūta jaunu spēlētāju sarakstu mačiem).
* GET /admin/rounds:
  * rāda visus raundus ar mačiem un select/ radio uzvarētāja izvēlei.
* POST /admin/rounds/update:
    * pieņem formu ar winner_id katram mačam;
    * izmanto bracket_service.set_match_winner.
* GET /admin/reset:
    * rāda divas pogas: “Atstatīt progresu” un “Atstatīt visu turnīru”.
* POST /admin/reset/progress
* POST /admin/reset/all

# 10. Galvenās procesu plūsmas

## 10.1. Spēlētāju pievienošana

Admin ievada vārdu → sistēma pievieno spēlētāju turnīram (ja turnīrs nav sācies).

## 10.2. Bracket ģenerēšana

admin → nospiež “Ģenerēt nākamo raundu”:
- Spēlētāju pāri tiek randomizēti;
- Aprēķināts nepieciešamais BYE skaits;
- BYE mačiem uzvarētājs tiek piešķirts automātiski.

## 10.3. Rezultātu ievade

- Ievade ar punktiem vai manuāla uzvarētāja izvēle.
- Pēc raunda pabeigšanas automātiski tiek sagatavots nākamais raunds.

## 10.4. Turnīra noslēgums

- Pēc fināla un 3. vietas spēles statuss kļūst finished.
